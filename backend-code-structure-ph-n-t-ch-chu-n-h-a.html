2. Các vấn đề phát hiện

🔴 [P0] Entry point bị tách đôi — gây nhầm lẫn

apps/backend/server.ts là file chạy thực, nhưng src/app.ts và src/server.ts chỉ là shim export = require('../server'). Cả 3 file tồn tại song song không cần thiết.

🔴 [P0] shared/config/ trùng lặp config/

src/shared/config/databases.ts và src/shared/config/swagger.ts là bản copy/re-export của src/config/databases.ts và src/config/swagger.ts. Hai nguồn sự thật gây sync-lag.

🔴 [P0] third-parties/sports/gnews/ duplicated trong third-parties/providers/GNews/

GNewsProvider và NewsService xuất hiện ở cả 2 đường dẫn, logic bị phân kỳ khi cập nhật.

🟡 [P1] lib/ và utils/ quá nhỏ — không cần tầng riêng

src/lib/ chỉ có 1 file (prismaAdmin.ts), src/utils/ chỉ có 1 file (redis.ts). Cả 2 nên được hợp nhất vào src/config/ hoặc src/shared/.

🟡 [P1] services/emailService.ts cô đơn không theo chuẩn

1 file duy nhất trong src/services/, trong khi emailService đã có bản chính tại src/shared/services/emailService.ts — gây nhập nhằng.

🟡 [P1] automation/ (2 files) có thể merge vào modules/workers/

businessEvents.ts và depositSyncWorker.ts là background workers; đã có 14 workers trong modules/workers/. Việc tách thư mục mà không có tiêu chí rõ ràng tạo ra overhead.

🟡 [P1] modules/auth/ chỉ có 1 controller

Toàn bộ auth logic nằm trong shared/services/authService.ts và shared/routes/auth.routes.ts. Module auth/ chỉ có otpController.ts — cần hợp nhất hoặc expand thành module đầy đủ.

🟡 [P1] Game providers bị tách 3 nơi
  • src/modules/game/services/providers/ — provider runtime (GSC, Goldgate, TCGaming)
  • src/shared/services/aggregators/ — GSCService, GoldgateService, TCGamingService
  • src/third-parties/providers/GSC|Goldgate|TCGaming/ — HTTP clients

Ba tầng cho cùng 1 nhà cung cấp, không có boundary rõ ràng.

🟡 [P1] modules/game/services/payments/ trùng với shared/payment/

PaymentFactory xuất hiện ở cả 2 nơi. Module game tự quản lý payment riêng thay vì dùng shared adapter.

🟡 [P1] modules/admin/management/ đặt sai chỗ

CLI commands (backup, deploy, health, logs…) là devops tooling, không phải runtime module. Nên nằm ở scripts/ hoặc tools/ ngoài src/.

🟡 [P1] modules/admin/ops/ chứa business logic lẫn workers

ops/analytics/, ops/automation/, ops/financial/ là các service độc lập nhưng bị nhúng sâu trong admin module. Các service này dùng chung cho nhiều modules.

🟡 [P2] core/ lẫn lộn domain logic và infrastructure

core/strategies/ (lottery win-checker) là business logic thuần túy. core/utils/distributed-lock.ts là infrastructure. Nên tách thành core/domain/ vs core/infra/.

🟡 [P2] Test files phân tán không đồng nhất

Tests nằm ở 4 vị trí khác nhau: src/__tests__/, src/shared/middlewares/__tests__/, src/modules/trade/services/__tests__/, src/__tests__/modules/.

6. Quy tắc chuẩn hóa cần tuân thủ

Naming Convention
  • Controllers: xyzController.ts
  • Services: xyzService.ts
  • Routes: xyz.routes.ts
  • Validators: xyzValidator.ts
  • Workers: xyz.worker.ts
  • Strategies: xyz.strategy.ts
  • Tests: xyz.test.ts cạnh file
Folder Size Rule
  • Folder phải có ≥ 3 files để tồn tại độc lập
  • Nếu < 3: merge vào folder cha hoặc sibling phù hợp
  • index.ts barrel bắt buộc cho mọi module
  • Không nested quá 4 cấp từ src/
Module Boundary
  • Module không import trực tiếp từ module khác
  • Cross-module: đi qua shared/
  • Mỗi module có config/project.config.ts riêng
  • Payment luôn qua shared/payment/
Layering Order
  • config/ → cơ sở hạ tầng
  • core/ → domain logic thuần
  • third-parties/ → external API clients
  • risk/ → security engines
  • shared/ → cross-cutting services
  • modules/ → feature slices (top layer)

7. Tổng kết điểm mạnh hiện tại

✅ Kiến trúc multi-project tốt

6 databases riêng biệt (hub, game, trade, dating, sports, admin) + Prisma multi-client factory — scale theo từng project.

✅ Vertical slice modules hoàn chỉnh

Mỗi module (game, dating, sports, trade) có đầy đủ config/, controllers/, services/, routes/, validators/ — dễ onboard và maintain.

✅ Third-party abstraction tốt

ServiceRegistry + BaseProvider pattern cho phép thêm/bớt provider mà không thay đổi business logic.

✅ Risk engine tách biệt hoàn toàn

src/risk/ là module độc lập, không phụ thuộc Express, dễ test unit và tái dụng.

✅ server.ts production-ready

Sentry, CORS, Helmet, Rate limiter, i18n, Graceful shutdown, Socket.IO Redis adapter, Prometheus metrics — đầy đủ.
