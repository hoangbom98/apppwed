3.1 TC-Gaming Seamless Wallet Integration (DES-ECB + SHA256)

Đây là kỹ thuật quan trọng nhất. LKVIP đang tích hợp TC-Gaming — BoYue đã làm xong và đang chạy production.

🎯 Flow TC-Gaming đầy đủ
1. Đăng ký user trên TCG
   → Backend gọi TCG API (method=cm)
   → Payload mã hóa bằng DES-ECB
   → TCG trả về prefix username (VD: "14btimibbs")

2. Launch game
   → Backend gọi TCG (method=lg)
   → TCG trả về launch URL có token

3. TCG Callbacks → Backend endpoints:
   ├─ sgb (get_balance)    ← Kiểm tra số dư
   ├─ db  (debit)          ← Trừ tiền (đặt cược)
   ├─ cr  (credit)         ← Cộng tiền (thắng cược)
   ├─ rv  (reserve)        ← Tạm giữ
   ├─ cfr (confirm)        ← Xác nhận
   └─ rcr (rollback)       ← Hoàn tiền

4. Background Worker sync bet history (mỗi 30s)
   → method=get_bet_history
   → Insert vào DB với idempotency check (ref_no)
AspectChi tiết
Mã hóa payloadDES-ECB (dùng phpseclib3 — tương thích PHP 8.x)
Signature verifySHA256(body + secret) — validate mọi callback
IdempotencyCheck ref_no trước khi xử lý — tránh double charge
Currency1 VNDK = 1000 VND — luôn convert
No JWTEndpoints TCG callback không cần auth JWT

3.3 AES-256 Encryption cho Admin API

Toàn bộ request/response giữa Admin Panel và Backend đều được mã hóa AES-256-CBC — bảo vệ sensitive data ngay cả khi bị MitM.

// Middleware pattern:
if (config('app.encryption_enabled')) {
    // Decrypt incoming request body
    if ($request->header('X-Encrypted')) {
        $body = AES_decrypt($request->body, $key);
    }
    // Process normally...
    // Encrypt outgoing response
    $response = AES_encrypt($data, $key);
    return response()->json(['data' => $response]);
}

Học hỏi — LKVIP admin dashboard nên implement tương tự cho các API nhạy cảm (balance adjustment, user ban, payment approve).

63 Fix QUAN TRỌNG nhất từ BoYue

Fix #1: Frozen Balance (Wallet Race Condition)

BoYue dùng 2 fields tách biệt: coin (available) + fcoin (frozen). Khi user đặt cược, tiền move từ coin → fcoin. Nếu thắng → fcoin → coin. Nếu thua → fcoin = 0.

Không có frozen balance → có thể xảy ra race condition khi user đặt cược nhiều game cùng lúc và balance âm.

-- Prisma schema cần thêm:
model Wallet {
  balance       Decimal @db.Decimal(16, 2)
  frozenBalance Decimal @db.Decimal(16, 2) @default(0) // ← THÊM
}
Fix #2: TC-Gaming Idempotency (Tránh double credit)

BoYue check ref_no UNIQUE trước mọi credit/debit từ TCG. Nếu ref_no đã tồn tại → return success ngay (idempotent). Không có check này → TCG retry → user được cộng tiền 2 lần.

-- Table cần có:
CREATE UNIQUE INDEX idx_ref_no ON tcg_wallet_transactions(ref_no);

-- Trong code (Node.js):
const existing = await prisma.tcgTransaction.findUnique({ where: { refNo } });
if (existing) return { balance: await getBalance(uid) }; // idempotent
Fix #3: DECIMAL cho money fields (Không dùng Float)

Float/Double có lỗi làm tròn nhỏ (0.1 + 0.2 ≠ 0.3). Với tiền tệ, sai số này tích lũy và gây mất cân đối sổ sách. BoYue dùng DECIMAL(16,2) strict cho 100% money fields.

// Prisma schema - kiểm tra:
model Wallet {
  balance Decimal @db.Decimal(16, 2)  // ✅ ĐÚNG
  // balance Float                   // ❌ SAI
}
