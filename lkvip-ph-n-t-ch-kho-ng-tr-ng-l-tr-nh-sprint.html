Trading App — Công nghệ & Tích hợp

Thực trạng
Vite 8 + React 19 + TypeScript 6 ✓
Shared packages
@lkvip/ui, @lkvip/types, @lkvip/constants đã là dependency
Sự thật: Trading app không còn dùng React 17 + CRA. Codebase đã là @lkvip/trade với Vite 8, React 19, TypeScript 6, pnpm workspace — đúng chuẩn monorepo. Backend trade module đầy đủ tại apps/backend/src/modules/trade/ với services: orderMatchingService, tradeWalletService, marketPriceFeed, tradeKycService.

Khoảng trống thực sự còn lại (từ trading-optimization-plan.md):

  • Chưa replace SVG chart bằng TradingViewWidget từ @lkvip/ui
  • 5 trang còn thiếu: /watchlist, /shop, /signin-reward, /news + wiring 2FA
  • Các API tương ứng đã có trong src/api/trade.ts nhưng chưa có UI page
2
Cross-app Integration / API Gateway
Thiếu gateway — auth đã per-project
Auth hiện tại
JWT per-project trong auth.ts middleware — token có project claim, cô lập chéo project ✓
Routing
Nginx proxy tất cả về 127.0.0.1:5000 — 1 backend duy nhất, không cần extra gateway
Sự thật: Đã có projectResolver middleware xác định project từ path/host/header. JWT enforce project-claim isolation. @lkvip/constants chứa PROJECT_IDS dùng chung. Nginx đã là reverse proxy. Không cần thêm Express proxy layer — sẽ tăng latency vô ích.

Việc cần làm thực sự:

  • Tạo package @lkvip/auth chứa hook useAuth, token refresh logic, apiClient cho frontend (hiện mỗi app tự viết)
  • Nginx rate-limiting per upstream nếu chưa có
  • Không cần thêm Express gateway — backend đã là single API
3
Module Registry & Super Admin
Thiếu hoàn toàn — ưu tiên cao
Feature Flags hiện tại
Có seed:flags script và ui-config per-project, nhưng không có API bật/tắt module động
Admin dashboard
Có ThemeLivePreview, GeneralSettings nhưng không có Module Registry UI
Khoảng trống thực: Không có schema Module / Feature trong 6 Prisma schemas. Không có endpoint /admin/modules. Không có frontend hook useFeatureFlag(). Cần thiết kế từ đầu.
  • Thêm model FeatureFlag vào admin_db schema với fields: key, project, enabled, config
  • Tạo endpoint GET /api/shared/features?project=X (public, cached) và PUT /api/admin/features/:key (admin)
  • Tạo hook useFeatureFlag(key) trong @lkvip/ui
  • Tích hợp vào admin-dashboard: trang quản lý bật/tắt module theo project

Testing — Unit Test Coverage
Gần như bằng 0 — rủi ro cao
Tests hiện có
1 file integration test (multiTenant.test.ts) + load tests. Zero unit tests trong apps/backend/src/
CI pipeline
Jest config sẵn sàng, pnpm test --coverage chạy trong GitHub Actions nhưng pass nhờ --passWithNoTests
Rủi ro: CI hiện pass dù 0 test vì --passWithNoTests. 298 Prisma models + 11 risk detectors + payment adapters không được test = không có safety net khi refactor.

Ưu tiên viết tests:

  • Critical: orderMatchingService.ts, tradeWalletService.ts — tài chính cần test đầu tiên
  • High: riskMiddleware.ts, các payment adapter (MoMo/ZaloPay/VNPay)
  • Medium: auth.ts middleware, projectResolver.ts
  • Bỏ --passWithNoTests sau khi đạt coverage > 30%

Logging & Monitoring tập trung
Winston có — chưa tập trung
Đã có
Winston logger, /health endpoint (JSON status:"healthy"), /metrics endpoint, @sentry/node là dependency trong backend
Thiếu
Sentry chưa khởi tạo trong server.ts; Frontend chưa có Sentry; Chưa có alerting tự động
Quick wins: @sentry/node đã được install — chỉ cần thêm Sentry.init() và Sentry.Handlers vào server.ts. Thêm SENTRY_DSN vào .env.
  • Backend: init Sentry trong server.ts (3 dòng code)
  • Frontend: thêm @sentry/react vào các SPA
  • Thiết lập UptimeRobot ping GET /health mỗi 1 phút
  • Alert Telegram khi error rate > ngưỡng (Sentry alert rule)
  • /health và /metrics đã sẵn sàng — không cần viết thêm

Bảo mật nâng cao (2FA, Audit, Session)
Cơ sở sẵn — chưa kích hoạt đầy đủ
Đã có
auditLogger.ts middleware, audit.ts util, rbac.ts, riskMiddleware.ts, Risk System đầy đủ 11 detectors
Thiếu
2FA chưa enforce cho admin login; Audit log chỉ log action chứ không log old/new value; Không có device management
Audit log hiện tại: auditLogger.ts chỉ log method + URL + userId + body. Không lưu before/after state. Không có UI xem audit log (trang AuditLogPage.tsx tồn tại trong admin nhưng cần verify data source).
  • Thêm TOTP 2FA cho admin: speakeasy + QR code — áp dụng cho role admin/superadmin
  • Nâng cấp auditLogger.ts: thêm previousValue, newValue, ipAddress
  • Session management: store deviceId, userAgent trong JWT; endpoint GET /auth/sessions + DELETE /auth/sessions/:id
  • Áp dụng auditLogger middleware cho tất cả admin routes (hiện có thể bị bỏ sót)

Môi trường Staging & ENV Management
Thiếu staging config
CI/CD
GitHub Actions CI đầy đủ (lint + typecheck + build + test). Deploy workflow có. Nhưng chỉ deploy thẳng production
ENV
Chỉ có .env.example, chưa có .env.staging template
  • Thêm .env.staging.example với staging DB URLs, staging API URLs
  • Thêm GitHub Actions job deploy-staging trigger trên push to develop branch

  • Cân nhắc dùng GitHub Environments để quản lý secrets staging vs production
